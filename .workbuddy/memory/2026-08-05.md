- 核心算法复用 ios-home-screen-prototype skill 的 reflow + attemptMove 骨架，并按截图规则微调（1×1 顺序排序、小→大仅在水平/垂直有空位才让位、多选基于首个图标判定、跨页原页 1×1 自动补位）。

- 迭代 2（15:17）：改为 4×6 网格（24 格）；拖动加入实时让位微动效（liveLayout 拖动中实时模拟布局并让其他元素平滑位移）；落位弹跳（dropped/dropBounce）、placeholder 呼吸（phPulse）、非法落位红色高亮；手机壳 340×700。校验通过。
- 迭代 3（17:02）：修复 1×1 挤压 1×1 时动效异常抖动。根因：① 鼠标在网格边界微动时目标格来回切换导致 1×1 序列反复让位；② 布局失败仍应用让位位置。修复：snapGrid 滞回取格（|delta|>=1.5 直接取整保持跟手，否则越格线 0.6 才切换）+ 仅目标格变化才重排（scheduleLive RAF 节流）+ 布局失败不应用让位（livePos=null）。仿真验证：旧算法边界微动切换 6 次→新算法 0 次，快速拖动保持跟手。
- 迭代 4（17:59）：实现真正的多选拖动。交互完善：长按 450ms 或按钮进入多选；点击图标切换选中（保序、黄色序号徽标）；点击空白退出；拖动任意已选元素整个集合跟手（锚点跟手，其余相对平移）；规则判定基于首个选中 leader（截图规则），leader 落点显示占位框并实时让位（liveLayoutFor 支持排除集合）；落位 multiPlace：leader 按单元素规则落位 + 其余按选择顺序从 leader 位置行优先紧密排列（orderedCells），放不下的放回原页（returnedCount 提示）；跨页时集合整体移动，目标页需能放下 leader。仿真 4 场景（空白/挤压/紧凑/半空）全部通过，无重叠越界重复。
- 迭代 5（08-06 10:53）：修复两问题。① 多选卡死/错误：根因是 multiPlace 同页时 els 引用断裂（filter 生成新数组但 els 未重新赋值，leader/rest push 进游离数组导致元素丢失）；且失败路径先破坏 pages 再返回。修复：multiPlace 改为**原子操作**（克隆 simPages 完整模拟，全量校验通过后才应用真实 pages）+ els 统一重新赋值 + render 保留多选集合 c<0 元素 + scheduleLive 用快照算 leader 偏移（跨页后 c/r=-1）+ 多选单击不切换选中态。② 拖起元素后原位空白实时补位改为**不补位**：liveLayoutFor 去掉全局 reflow，改为 applyChainShift 挤压链让位（1×1 插入时被挤链按快照位置接力平移），拖向空白时其他元素不动；互换/大→小/小→大仍实时反馈。自检 5 场景全过（同页/跨页/满页拒绝且 pages 未被破坏/链式让位/拖空白不补位）。
- 迭代 6（08-06 17:45）：规则修正——"大→小"被挤压的 1×1 也要被挤走。原实现 movers 只含非 1×1，1×1 仅靠松手后 reflow 重排，导致拖动实时预览中被覆盖的 1×1 不移动（与大元素视觉重叠）。修复：attemptMove C 分支 movers 改为全部被挤压元素（含 1×1），按面积降序逐个找空位放置。自检 3 场景（2×2 压 6×1×1 / 2×2 压 1×2+1×1 混合 / 1×2 压 1×1）全过：落位 ok、覆盖区无残留、无重叠。
- 迭代 7（08-06 17:53）：修复"实时让位"重大缺陷——liveLayoutFor 在"当前 els 状态"上增量计算（sim 从 els 克隆），而 applyChainShift 用"拖动前快照"计算，拖动过程中 els 位置/order 被让位更新，两套输入不一致导致连续拖动错乱（重叠→ok=false→让位失效）。修复：**每次实时让位都从拖动前快照重建输入**（sim 元素位置与 order 全取快照，de 的 order 也取快照），只写回位置、不写回 order（松手 reflow 统一重排）。自检 5 场景全过：连续插入往返 5 次、拖空白不补位、2×2 压 1×1、相邻格链式让位、随机序列连续拖动 9 次全部 ok 无重叠。
- 迭代 8（08-06 18:03）：修正"A·向空白处移动·1×1"松手行为——被拖元素**固定松手位置不变**，其他 1×1 基于排序填充剩余空格（原实现把 dragged 排到序列末尾滑离松手格）。新增 placeAtFixed（固定 dragged + 其余按 order 填空 + 按行优先重排 order）与 placeOrReflow（1×1 且目标格空白→固定，否则 reflow）；onUp 单元素与 multiPlace leader 落位统一改用 placeOrReflow。自检 6 场景全过：拖空白固定/中间空格固定/大→小/插入排序回归/order 行优先连续。
- 迭代 9（08-06 18:11）：实时让位改为 **iOS 式完整实时布局**——拖动元素时空出区域由 1×1 实时补位，布局基于拖动元素位置实时变更（替换"拖空白不补位 + 挤压链让位"方案）。liveLayoutFor 改为：快照重建输入 + attemptMove（挤压/互换/大小让位）+ **placeAtFixed（de 固定当前格，其余 1×1 按 order 补位填充剩余空格）**；删除 applyChainShift（挤压链接力平移被 placeAtFixed 的补位取代）。松手行为（placeOrReflow 固定位置）不变。自检 5 场景全过：拖空白原位被补位/连续拖动 10 次/挤压/大→小/松手固定回归。
- 迭代 10（08-06 18:26）：修复"1×1 前面不允许有空格"未严格执行——检测发现 dragged 固定到靠后位置时其前面（行优先更早）留下空格。修复：① placeAtFixed 的 others **优先填满 dragged 前面的空格**（再填后面）；② 新增 hasGapBefore 检测，placeOrReflow 中若 others 填不满 dragged 前面（仍有空格）则**降级为 reflow 序列排序放置**（dragged 落序列位），严格保证 1×1 前面无空格。物理本质：dragged 拖到"超出序列容量"的位置（前面空格 > others 数）必然降级。自检 4 场景全过（含 widget 混合场景），无违规。
