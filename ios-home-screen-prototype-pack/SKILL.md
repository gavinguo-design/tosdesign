# iOS 桌面主屏原型（手机首页布局）

## 概述

生成一个完整、可交互的 iOS 风格桌面主屏原型，单文件 HTML、零依赖、无构建步骤。
包含 iPhone 外壳（340×700，圆角 54）、状态栏、壁纸、应用网格（4×6）、Dock、分页点、
多页状态、多选模式、右侧实时规则判定面板与操作日志——以及完整的拖拽 / 排序 / 互换 /
实时重排 / 跨页 / 原子落位逻辑。

## 使用场景

- 用户需要一个 iOS 主屏 / 桌面 / 应用网格原型或高保真交互稿
- 需要在网站测试或 UI 走查中嵌入可交互的 iPhone 主屏
- 需要演示桌面图标拖拽、自动补位、大小组件互换、跨页拖动
- 需要展示"1×1 严格排序"、"相邻互换"、"实时布局变更"等桌面元素移动规则

## 使用方法

1. 将 `ios-home-screen.html` 复制到目标目录（文件完全自包含，浏览器直接打开即可）
2. 用 `present_files` 打开该 HTML（内建预览面板实时展示）
3. 需要调整时，按下方"定制参考"修改常量 / CSS / 脚本

## 功能清单

### 交互能力
- **拖拽**：任意元素按住拖动，滞回取格（边界微动不抖动，快速拖动跟手）
- **多选**：长按 450ms 或点"多选模式"按钮进入；点击图标切换选中（保序 + 黄色序号徽标）；点击空白退出；拖动任意已选元素整体移动集合
- **跨页**：拖到屏幕左/右边缘停留 420ms 翻页；**跨页优先级最高、一定成功**——目标页空间不足时把被挤元素挤出至后一页，后一页也放不下则**新建一页承接**（最后一页右缘右拖同样直接新建页）；原页 1×1 自动补位
- **增删**：工具栏可新增 1×1 / 1×2 / 2×1 / 2×2 / 4×2（满行大卡片）；非 1×1 新增时逐个候选位置做完整模拟（放置 + 1×1 重排），全部放得下才落位，否则提示"空间不足"（不会挤丢 1×1）；删除后 1×1 自动补位
- **规则面板**：右侧实时显示命中的移动规则分支（空白/同尺寸/大→小/小→大/多选）
- **操作日志**：记录每次移动/补位/跨页/放回/失败还原

### 动效与反馈
- 拖动元素放大 + 描边阴影；集合拖动轻微缩放半透明
- 占位框呼吸动画；非法落点红色高亮；落位弹跳（dropBounce）
- 跨页边缘高光提示；新页元素淡入
- 位置变化实时平滑过渡（CSS cubic-bezier）

## 完整规则（严格实现）

### 一、排序规则
| 元素 | 规则 |
|---|---|
| **1×1** | 严格从左到右、从上到下排序；1×1 之间不允许空隙（reflow 自动补齐，序号连续） |
| **非 1×1** | 位置相对固定，不参与自动排序；可自由拖放，允许空隙 |

- 补位不跨页，仅排序当前页面元素
- **1×1 前面不允许有空格（硬约束）**：拖动 1×1 到空白松手后，placeAtFixed 优先填满 dragged 前面的空格；若其他 1×1 数量不足以填满（仍有空格），降级为 reflow 序列排序放置——dragged 自动**吸附到序列末位紧凑位置**（iOS 式磁吸），保证整个 1×1 序列前面无空

### 二、移动场景（判定优先级 A → B → C → D）
**A. 目标格空白**
- 1×1 → 松手后**吸附到最近紧凑位置**（iOS 式磁吸：前面无空隙的序列末位），其他 1×1 基于排序填充剩余空格
- 非 1×1 → 直接放置；松手后空隙由 1×1 补齐

**B. 同尺寸互换**
- 1×1 → **相邻（上下左右，曼哈顿距离 1，不含斜对角）直接互换位置与 order**；不相邻走插入补位排序
- 非 1×1 → **目标相邻方向有空隙则沿方向平移一格让位（多空隙优先反方向）；无空隙直接交换**（E 回到被拖元素原位）

**C. 大 → 小**（大元素可完整覆盖小元素区域）
- 无论空满屏均可直接移动；落位后被挤压的**所有元素（含 1×1 与非 1×1）**挪到空位（大块优先放置）；1×1 重新排序

**D. 小 → 大**
- 被压大元素水平/垂直方向有足够空隙才可让位（优先拖入方向的反方向）；无空位则**禁止移动**

**从当前页移走（跨页）**：留下的空位由本页其他 1×1 自动补位

### 二·B 跨页放置（优先级最高，**一定成功**）
跨页不再拦截，统一走 `crossPagePlace`，目标页放不下就把内容往后挤：
| 场景 | 行为 |
|---|---|
| 目标落点空闲 | 直接放置，原页 1×1 补位 |
| 1×1 占 1×1 | 被占者在目标页内依次后移；溢出到页尾的 1×1 挤到后一页 |
| 1×1 占非 1×1 · 该 widget 周围有空隙 | widget 让位（优先拖入方向的反方向），dragged 落目标格 |
| 1×1 占非 1×1 · widget 处于 1×1 序列末位 | 该 widget 整体挤到后一页 |
| 1×1 占非 1×1 · widget 非末位 | widget 保持不动，仅把末位元素挤到后一页 |
| 非 1×1 占非 1×1 | 末位 widget 挤到后一页；非末位依次向后挤走末位元素 |
| 后一页也放不下 | **新建一页**承接被挤元素（多元素挤出视为整体，不拆散） |

### 三、多选拖动（基于体验完善）
- 进入：长按 450ms 或按钮；选择：点击切换（保序 + 序号徽标）；退出：点击空白
- **仅 1×1 元素可加入多选**（截图规则；点击非 1×1 提示"仅 1×1 元素可多选"）
- 拖动：按住任意已选元素，集合整体跟手（锚点跟手、其余保持相对像素偏移）
- **规则判定基于首个选中（leader）的尺寸**（A→B→C→D 复用；多选落位禁用相邻互换 noSwap——集合语义走插入/排序，避免 swap 目标格被补位占用失败）
- 落位（`multiPlace`，整组插入法）：leader 按单元素规则落位并固定 → 其余元素**紧跟 leader 之后插入 1×1 序列**（按选择顺序连续，后续 1×1 order 顺延）→ reflow 统一落位。这样整组**严格连续**，而不是散落到远处空位
- **放不下的放回原页**（跨页回原页 reflow；同页留在本页找空位）（日志提示 N 个放回）
- **落位后 `renumberOrders` 按行优先重排各页 1×1 order**（rest 排列后 order 保持旧值会重复/空洞 → 后续拖动错乱，必须重排）
- 跨页：集合整体移动，目标页放不下时同样走挤出/新建页

### 四、拖动过程（单选不补位 / 多选补位）
- **单选拖动**：其他元素保持原位不动，只用占位框预览落点有效性；松手后一次性按规则落位
- **多选拖动**：拖起即由当前页其他 1×1 **实时补位**，并随目标格变化持续重算
- 多选实时补位会写回真实布局（`drag.liveDirty`）；若最终**未移动**（单击/微动松手）必须 `restoreAll()` 还原，否则补位元素与跟随复位的集合元素产生**数据层重叠**
- 每次目标格变化即重算布局：**快照重建输入**（snapMap，位置与 order 全取拖动前快照）保证连续拖动稳定不漂移
- 实现：`liveLayoutFor` = 快照重建 + `attemptMove`（挤压/互换/大小让位）+ `placeAtFixed`（dragged 固定当前格，其余按 order 补位填充）

### 五、原子落位（多选 / 失败零副作用）
- `multiPlace` 在**克隆的 simPages** 上完整模拟（移除集合 → leader 落位（noSwap）→ rest 插入 order 序列 → reflow → 放不下的放回原页 → **renumberOrders 重排各页 order** → 全量校验无重叠无未放置），**通过后才应用到真实 pages**
- 失败时 pages 不被破坏，配合 pagesSnapshot 整体还原——不会丢元素、不会卡死
- 跨页落位 `crossPagePlace` 同样先在克隆页模拟，再决定挤出/新建页

### 六、交互机制（体验层）
1. **滞回取格 snapGrid**：|delta|≥1.5 直接取整保持跟手；否则越过格线 0.6 才切换（死区 0.4~0.6），边界微动不抖动
2. **RAF 节流**：仅目标格变化才重排，动画不被频繁打断
3. **跨页动效**：边缘高光 + 停留 420ms 翻页；跨页一定成功（挤出/新建页承接），无"空间不足拦截"
4. **视觉反馈**：占位框呼吸、非法红色高亮、落位弹跳、拖动放大描边
5. **操作日志**：每次操作实时记录（成功/失败/跨页/放回/还原）

### 六·B 拖动实时反馈层（纯视觉，不参与规则判定）
- **拖起聚焦**：`grid.is-dragging` 让其他元素降透明度/降饱和后退，突出被拖元素；拿起瞬间 `lifted` 阴影上浮
- **长按进度环**：按下即出现白色环形进度（conic-gradient + `@property --lp` 动画，450ms 转满进入多选）；不支持 @property 时退化为呼吸缩放，无副作用
- **目标格到位脉冲**：目标格每变化一次，占位框 box-shadow 闪一下 + `navigator.vibrate(4)` 轻触感
- **被挤元素预览高亮**：拖向已占位置时，将被挤压/让位的元素先打上白色虚线外框（`will-push`），用户提前知道谁会动
- **无效落点红光圈**：规则不允许时红色描边直接打在被拖元素上（占位框会被拖动元素盖住，提示必须落在它看得见的地方）
- **落位反馈**：成功 → 目标格白色扩散光环（`ripple`）+ 震动；失败 → 红色光环 + 元素水平抖动（`shake`）+ 三段震动
- **边缘翻页进度光带**：贴边停留时边缘光带从 0 填充到 66px（420ms 与翻页计时同步），左右边缘切换会重新计时
- **多选拖尾**：集合非锚点元素保留 60ms 位移延迟，产生轻微"橡皮筋"跟随感；集合元素平移被 clamp 在网格范围内（散开的集合贴边可见，不会拖出屏幕）
- **render 状态保持**：`render()` 会重置 className，拖动中状态（dragging/lifted/multi-drag）在 render 内重新挂上，翻页后视觉不断档

## 定制参考

- **布局常量**（`<script>` 顶部）：`COLS`、`ROWS`（默认 4×6=24 格）、`CELL`（54px）、`GX`/`GY`（列距 14 / 行距 20）、`PAD`
- **手机壳 / 壁纸**：`.phone`（340×700，圆角 54）、`.screen`（4 色壁纸渐变）
- **元素类型**：`TYPES` — `1x1`、`1x2`、`2x1`、`2x2`、`4x2`（4 列满行 × 2 行高，仅可放 c=0）；工具栏可增删；4×2 专属大字号样式 `.w4x2`
- **配色**：`PAL` 渐变对数组；**角标**：`e.badge`（红底白字）
- **Dock**：`.dock`（280×76，圆角 34，4×54×54 图标）
- **初始数据**：修改 `seed()` 函数（底部）可自定义 3 个默认页面

- 逻辑经浏览器自动化回归验证（58 项全 PASS）：Xmind 新规则 22 项（拖动过程/跨页挤出/边缘新建页/同页 A→D 分支）+ 既有 36 项（单元素/多选/跨页/4×2/还原/删除后还原）
- 添加非 1×1 时用「候选位置 + 克隆模拟」保证不会挤丢 1×1：找不到能容纳全部 1×1 的位置就拒绝并提示
- 切换到横屏 6×4 或其他尺寸：改 `COLS`/`ROWS` 与 `.grid` 尺寸即可，算法自动适配
